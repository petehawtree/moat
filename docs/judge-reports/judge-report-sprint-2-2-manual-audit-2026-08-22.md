## Findings

### Critical

None.

### High

1. **Debt that cannot be serviced is labelled `unavailable`, not `fail`.**
   `moat/screen/quant_screen.py` deliberately returns an absolute-floor
   failure when debt is positive and FCF is missing or non-positive. But
   `_metric_status()` then checks the derived debt ratio (`None`) first and
   overwrites that known failure as `unavailable`. The quality score excludes
   unavailable metrics, so this makes a real debt failure disappear from the
   denominator. On the latest run, this affects 109 debt rows, including 17
   companies that pass the screen; nine (CBRE, DLTR, ETR, FCX, KMB, PEP, ROK,
   URI, VLO) would fall below the 50% threshold if that debt failure were
   counted. This is a current-scope data-integrity error, not a deferred
   feature.

2. **Financial-sector scores use metrics acknowledged to be definitionally
   invalid for banks and financials.** `docs/PRD_ADDENDUM.md` §A13 says FCF
   margin, debt/FCF, and gross margin do not describe a bank and that
   sector-relative ranking cannot fix invalid definitions. The application
   nevertheless presents a completed Sprint 2 screen across the current
   universe, which includes financial companies. This contaminates live
   current-scope scores, so it cannot be downgraded to DEFERRED simply because
   per-sector metric selection is planned later.

### Medium

None.

### Low

1. **The cache API’s stated default does not match its implementation.**
   `fetch_company_facts()` says its default cache age is
   `FUNDAMENTALS_CACHE_MAX_AGE_DAYS`, but its parameter defaults to `None`,
   meaning use cached data indefinitely. The production pipeline passes 90
   explicitly, and the verification tool currently relies on the indefinite
   cache behavior, so this is not the source of the current scoring failure;
   it is an error-prone public-function contract and has no regression test.
